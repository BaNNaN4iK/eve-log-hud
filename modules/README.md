# Модули EVE Log HUD

Каждая возможность приложения сверх чтения логов — отдельный модуль в своей папке.

| Модуль | Что делает | Вид |
|---|---|---|
| `overlay` | Окно поверх игры: урон, ремонт, баунти, добыча, угрозы, ручные сессии, окно флота | отдельный процесс |
| `fleet` | Флот напрямую из игры (ESI): состав, время, отлучки от босса, отметки ФК, история | трекер + вкладка |
| `appraisal` | Оценка предметов по ценам хабов, как Janice | трекер + вкладка |
| `reprocess` | Переработка: выход руды, льда, модулей по навыкам и месту, «переработать или продать», добыча из сессии | трекер + вкладка |
| `damage_types` | Чем бьёт враг: ЭМ / термо / кинетика / взрыв (справочник из SDE) | трекер |
| `alliance_auth` | Отправка итогов сессий в плагин Fleet Watch на сервере Alliance Auth | трекер |

## Установить, выключить, удалить

- **Установить** — распаковать архив модуля в папку `modules` рядом с программой (получится `modules/<id>/…`) и перезапустить.
- **Выключить, не удаляя** — вкладка «Модули» в окне программы. Выбор хранится в `config.json`, ключ `"modules"`.
- **Удалить** — удалить папку модуля.

Модули не зависят друг от друга. Например, без `damage_types` оверлей просто не покажет типы урона,
а без `fleet` не появится окно флота.

## Как устроен модуль

```
modules/<id>/
  module.json      описание
  <entry>.py       код для трекера: функция setup(ctx)            — или —
  <process>.py     отдельная программа (как оверлей): функция main()
  tab.js           вкладка страницы (необязательно)
```

### module.json

```json
{
  "id": "hello",
  "name": "Привет",
  "description": "Что делает модуль — одной-двумя фразами для вкладки «Модули».",
  "version": "1.0.0",
  "entry": "hello.py",
  "web": ["tab.js"],
  "default": true
}
```

- `id` — латиница, цифры и `_`, совпадает с именем папки.
- `entry` — код для трекера; `process` — вместо него, если модуль — отдельная программа.
- `web` — файлы, которые страница может загрузить (`.js`, `.css`, `.png`, `.svg`). Остальные файлы папки не отдаются.
- `default` — включён ли модуль сразу после установки.

### setup(ctx) — что ядро даёт модулю

```python
def setup(ctx):
    ctx.get("/api/hello", lambda qs: {"ok": True})                 # GET: dict → 200, (код, dict), modkit.Html
    ctx.post("/api/hello", lambda body, qs: {"ok": True})          # POST: body — разобранный JSON
    ctx.on_session(lambda rec: ...)                                # завершилась сессия (итог, как в sessions.jsonl)
    ctx.on_live(lambda session: session.update(extra=1))           # дописать поля в живые сессии
    ctx.status("hello", lambda: {...})                             # своё поле в /api/live
    ctx.thread(worker, "hello")                                    # фоновый поток (ctx.stop — сигнал остановки)
    ctx.on_stop(cleanup)
```

Также доступны `ctx.cfg`, `ctx.data_dir`, `ctx.watcher`, `ctx.online` (ESI; `None`, если онлайн выключен),
`ctx.port`, `ctx.core` (само ядро), `ctx.dir` (папка модуля), `ctx.log`.

Правила:
- Только стандартная библиотека Python: модуль должен работать в собранном exe без установки пакетов.
- POST-запросы ядро принимает только со страницы приложения (проверка Origin), модулю это делать не нужно.
- Ошибка в модуле не роняет трекер: модуль помечается «ошибка при запуске», остальные работают.
- Файлы писать через `ctx.core.replace_file` / `ctx.core.atomic_write_json`: на компьютерах с корпоративной
  защитой Windows обычное `os.replace` может не сработать.

### tab.js — своя вкладка

```js
(function (ELW) {
  if (!ELW) return;
  ELW.addTab({
    id: 'hello', title: 'Привет',
    css: '.hello b { color: var(--accent) }',
    html: '<section class="panel"><h2>Привет</h2><div id="helloBody"></div></section>',
    render: function () { ELW.$('helloBody').innerHTML = '<b>' + ELW.esc('мир') + '</b>'; }
  });
})(window.ELW);
```

`window.ELW`: `api(path, opts)`, `esc`, `L` (форматирование чисел и дат), `table`, `empty`, `icon`, `tile`, `$`,
`S` (состояние страницы, `S.tab` — открытая вкладка), `render()`, `base`.

## Тесты

`python -m unittest discover -s tests` в корне проекта проверяет и ядро, и все модули из этой папки.

## Обновления

Приложение раз в 6 часов (и по кнопке «Проверить сейчас» на вкладке «Модули») сверяет версии с последним выпуском
(Release) репозитория на GitHub. Если у модуля вышла новая версия — рядом появляется кнопка «Обновить»,
новые модули можно «Установить». Архив скачивается только с GitHub, сверяется по SHA-256 из `modules-index.json`
выпуска, старая версия откладывается в `modules/.old/`. Изменения вступают в силу после перезапуска.
Новое приложение целиком (exe) ставится вручную: ссылка на выпуск появляется там же.

Выключить проверку — `"update_check": false` в `config.json`; другой репозиторий — `"update_repo": "владелец/репозиторий"`.

Выпуск: `python build_app.py` собирает `dist/EveLogHUD-<версия>.zip`, `dist/modules/<id>-<версия>.zip` и
`dist/modules/modules-index.json` — все эти файлы прикладываются к выпуску. Чтобы модуль обновился у пользователей,
поднимите `version` в его `module.json`. Если модулю нужна новая версия ядра — укажите `"min_app": "2.3.0"`.
